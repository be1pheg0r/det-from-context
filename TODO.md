# TODO — детекция с переиспользованием временного контекста

**Задача:** блок памяти для DETR, хранящий состояние прошлых предсказаний
(queries / боксы / фичи инстансов) и переиспользующий его на будущих кадрах.
Базовый детектор — RF-DETR. Данные — ImageNet VID (основной), OVIS (стресс-тест
на окклюзии).

Литобзор: [Notion](https://app.notion.com/p/3bbaa037259b81eea3e2c0c17e3380b4)

## Правило про тесты

Тесты в `tests/` **не импортируют torch**. Они проверяют совместимость
контрактов, валидность конфигов и логику индексации кадров — то, что ломается
тихо и обнаруживается через полчаса запуска обучения. CI ставит только pytest.

Тяжёлые проверки (regression RF-DETR, forward/backward веток памяти) гоняются
руками через `tools/cli.py smoke` — в CI им делать нечего.

## Главное правило

Владельцы модулей не импортируют реализации друг друга — только
`context_detection.contracts`. Меняешь контракт → согласовываешь с Человеком 1,
а не правишь у себя.

## Что говорит литобзор (короткая версия)

Переход от «окна соседних кадров» к **детекции как поддержанию состояния сцены**.
Слот памяти = `content emb + явный anchor-box + timestamp + motion + confidence
+ age + observability`. Пять операций: создание → выравнивание → чтение →
селективная запись → завершение жизни слота.

Незакрытый участок литературы — не ещё один cross-attention, а **управление
жизненным циклом памяти**: когда создать слот, обновить, заморозить при
окклюзии, признать устаревшим, удалить.

## Известные грабли (учитываем с самого начала, а не потом)

| # | Проблема | Источник | Кто закрывает |
|---|---|---|---|
| 1 | Memory-queries душат детекцию новых объектов | MOTR → MOTRv2 | 3, 4 — раздельные источники гипотез, слияние после |
| 2 | Рекуррентный вход ломает венгерский матчинг | DN-DETR, Sparse4D v3 | 3, 5 — denoising с первого дня |
| 3 | State drift от безусловной записи в слот | TSA | 4 — гейт записи |
| 4 | Слепая пропагация без компенсации движения | StreamPETR MLN, HAT | 4 — motion в слоте |
| 5 | Train–inference gap (учим на 2–3 кадрах, гоняем на сотнях) | RecurrentBEV, GenVIS | 5 — замер по длине истории |
| 6 | Агрегированный AP не показывает эффект памяти | Hippocampus-DETR (53.0536 → 53.0539) | 5 — сетка по режимам отказа |

### Что зафиксировано в контрактах (читать перед стартом)

- **Порядок на кадре**: reset → encode → read → fusion → forward → write →
  detach. Живёт в `ContextDetector.forward`, менять только через Человека 1.
- **`initial_queries` вынесен из forward** — иначе memory-модуль не может
  прочитать память ДО декодирования, не форкая код детектора.
- **read / write разделены** — гейт записи (TSA) существует, только если write
  может решить не писать.
- **`query_delta=None`, а не нули** — `NoContext` обязан быть побитово равен
  детектору без обёртки, иначе baseline для всех ΔAP не является baseline.
  Поле **без дефолта**: `None` — осмысленный ответ, и ветка обязана произнести
  его явно. Забытое поле с дефолтом тихо выродило бы прогон в baseline с ΔAP=0,
  что читается как «память не помогает» вместо «память не подключена».
- **`make_dummy_batch` неоднороден намеренно**: элемент 0 — начало сцены
  (`is_sequence_start=True`, истории нет), элемент 1 — частичная история,
  остальные — полная. Однородный батч не заходит в `reset` ни разу, и утечка
  памяти между сценами не ловится ни одним прогоном.
- **`gated_residual` стартует с bias −2** — память открывается, только если
  реально помогает. Иначе первые эпохи она подмешивает шум в необученные
  queries, и это выглядит как «память не работает».
- **Валидаторы ловят на границе**: боксы вне [0,1], `time_offset ≤ 0` в
  валидном слоте (утечка будущего), ненулевые offsets в слотах-заглушках,
  рассинхрон B и device, NaN в `query_delta`, отрицательный age.

### Открытые вопросы (решить до старта, а не по ходу)

- **Двойной прогон backbone у RF-DETR (Человек 3 + Человек 1).**
  `ContextDetector.forward` зовёт `initial_queries(batch)`, затем
  `detector(batch, query_init=...)`. У `DummyDetector` первое — бесплатный
  `nn.Embedding`, и это маскирует проблему. У RF-DETR queries выбираются из
  выхода энкодера (two-stage), значит backbone прогонится дважды: ~2×
  латентность на модели, чей аргумент — неглубокий decoder. Варианты: кэш
  фич внутри адаптера или callback вместо отдельного метода. Не начинать
  `RFDetrAdapter`, не выбрав.
- **Форма `encoded_context` (Человек 3 + Человек 4).**
  `encode_context_frames` у `DummyDetector` отдаёт `[B, K, C_i, H_i, W_i]`, а
  `DetectorOutput.features` — `[B, C_i, H_i, W_i]`. Это единственный вход в
  `ContextModule.read`, который не является провалидированным контрактом.
  Зафиксировать раскладку до того, как `ContextCrossAttention` будет написан
  против угаданной.
- **Стоимость валидации на GPU (Человек 5, после первого профиля).**
  Валидаторы делают ~B+4 переноса на хост за шаг; на CUDA каждый — это
  синхронизация. Точка апгрейда названа в докстринге `contracts.py`:
  `model_construct` на горячем пути engine, валидация остаётся в тестах и на
  границах датасета.

## Человек 4 — Context и memory-модули

**Результат:** несколько веток памяти за одним интерфейсом, сравнимых между
собой.

Порядок по возрастанию сложности — не начинать со сложного:

- [ ] `NoContext` — пустой контекст, baseline. Должен проходить regression
      Человека 3
- [ ] `EMASlot` (MeMOTR) — экспоненциально сглаженное состояние объекта +
      attention к нему. Самая простая рабочая память, первый реальный сигнал
- [ ] `ContextCrossAttention` — queries читают K закодированных контекстных
      кадров. Формально это feature-level ветка (TransVOD/FAQ), нужна как
      **ablation-контроль** «query-level против feature-level», а не как
      основная ветка
- [ ] `StreamQueue` (StreamPETR) — FIFO top-K queries + motion-aware
      выравнивание. Референс-архитектура
- [ ] `BridgeADMemory` — в памяти лежат прошлые **предсказания о будущем**,
      retrieval по целевому моменту времени, а не по свежести. Другая схема
      адресации, отдельная ветка
- [ ] Гейт записи (TSA): слот не перезаписывается, когда объект не наблюдается
      — **грабля №3**. Обучаемая активация без supervision по видимости
- [ ] `MemoryState.detach()` / `.reset(mask)` — обрыв BPTT и сброс между
      последовательностями
- [ ] Компенсация движения при чтении — **грабля №4**. Начать с constant
      velocity; библиотека гипотез (HAT) — второй заход
- [ ] Fusion-режимы как параметр модуля: residual / gated residual /
      concat + projection
- [ ] Диагностика в `ContextOutput.diagnostics`: активных слотов, средний
      возраст, read weights, write rate, вытеснено слотов
- [ ] Тесты: нет NaN, маскирование работает, память не переносится между
      разными `sequence_id`, forward/backward на синтетической
      последовательности

**DoD:** `NoContext` проходит regression baseline; остальные ветки делают
forward/backward на синтетике; память не течёт между последовательностями.

## Порядок интеграции

1. Человек 1 замораживает контракты и dummy pipeline. **Блокирует остальных.**
2. Люди 2–4 параллельно пишут против контрактов.
3. Человек 5 стартует на dummy dataset/model, потом подключает реальные.
4. Milestone 1 — RF-DETR без контекста на ImageNet VID (совпадает с оригиналом).
5. Milestone 2 — `EMASlot` на коротком клипе, ненулевой ΔAP.
6. Milestone 3 — `StreamQueue` + гейт записи на длинной последовательности,
   заполнена сетка режимов отказа.
