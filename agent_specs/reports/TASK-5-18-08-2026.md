# Отчёт по TASK-5-18-08-2026: RF-DETR adapter и model component

Дата выполнения: 18.08.2026

## Результат

Мок `RFDetrAdapter` заменён рабочей тонкой головой над официальным
`rfdetr==1.9.0`. Архитектурный код RF-DETR не копировался: backbone, projector,
deformable decoder, prediction heads, загрузка checkpoints и исходный forward
принадлежат upstream-пакету.

RF-DETR оформлен по единому directory component protocol:

```text
models/rfdetr/
├── provider.py
├── config.yaml
├── README.md
└── artifacts/
```

Базовые experiment configs подключают этот provider через
`detector.component_path` и `detector.config_path`. Component config владеет
вариантом, полным upstream `ModelConfig` и источником весов; experiment config —
режимами freeze и параметрами context pipeline.

## Реализация адаптера

- Поддержаны актуальные upstream-варианты `nano`, `small`, `medium`, `large`.
- Полный YAML-блок `model` передаётся в Pydantic-схему выбранного upstream
  варианта: доступны architecture, decoder, queries/classes, resolution,
  refinement, precision/checkpointing и optional heads без локального
  дублирования схемы RF-DETR.
- Устаревший `base` исключён; базовая конфигурация переведена на `small` с
  разрешением 512.
- `query_init=None` вызывает исходный RF-DETR forward без изменения входных
  queries.
- Для context-веток временный PyTorch pre-hook подменяет только тензор на входе
  upstream decoder. Hook снимается в `finally` и не изменяет код или параметры
  RF-DETR.
- Decoder states, auxiliary predictions и multi-scale backbone features
  преобразуются в существующий `DetectorOutput`.
- `encode_context_frames` повторно использует upstream backbone для `[B, K]`
  context frames.
- `freeze` управляет параметрами upstream backbone и decoder.
- Относительные пользовательские checkpoints разрешаются от
  `models/rfdetr/`; отсутствующий файл отклоняется до начала обучения.

## Очистка legacy-кода

Самописная реализация RF-DETR в `src/context_detection/models/rfdetr.py`
полностью заменена тонким адаптером к upstream-пакету. Актуальный
`src/context_detection/models/losses.py` из `develop` сохранён: во время rebase
этот файл содержал более свежие изменения целевой ветки, не относящиеся напрямую
к адаптеру, поэтому задача не удаляет параллельную работу.

## Тесты

Добавлены шесть лёгких тестов без загрузки checkpoints:

1. regression-проверка равенства logits/boxes upstream forward и adapter при
   `query_init=None`;
2. подмена batch-specific queries перед decoder;
3. context feature encoding и freeze/unfreeze;
4. валидация варианта и передача пользовательского checkpoint;
5. сборка `ContextDetector` через настоящий `models/rfdetr` directory provider.
6. валидация полного component YAML официальным `RFDETRSmallConfig`.

## Документация и источники

Подробный пользовательский контракт добавлен в `docs/rfdetr.md`, а общий
`docs/component_protocols.md` обновлён с учётом directory provider.

Использованные upstream-источники:

- [официальный RF-DETR repository](https://github.com/roboflow/rf-detr);
- [RF-DETR 1.9.0 project metadata](https://github.com/roboflow/rf-detr/blob/develop/pyproject.toml);

- [официальный transformer/decoder](https://github.com/roboflow/rf-detr/blob/develop/src/rfdetr/models/transformer.py).

Полный прогон с настоящим checkpoint не включён в CI: он требует загрузки
весов и существенно тяжелее contract-тестов. При первом локальном запуске с
`weights: null` официальный пакет сам скачивает checkpoint выбранного варианта
в свой cache.
